    AI Helpers

    One GPU, one charter,
    every coding agent.

    A sovereign OpenAI-compatible gateway in front of your own GPU. It carries your team's standards, enforces rules that cannot be bypassed, and counts the context budget with the server's own tokenizer instead of trusting the client's estimate.

    Get started Read the source BSD-3-Clause · 422 tests · 0.1.0-alpha

    Why the server has to count

    On 2026-09-25 an agent session believed it was under its limit and sent 40,433 tokens to a server configured for 32,768. The server counted for real, refused the whole request, and the session died.

    The client was not lying. It was estimating, with its own tokenizer rule, which is more optimistic than the model's on French and on code. The gap was 55%. Every harness does this: Claude Code compacts at effective context − 13,000, an estimate about an estimate.

    The only party that can count correctly is the one holding the tokenizer, and that party is the server.

    Four stages, and the order matters

    Any client that speaks OpenAI speaks ai-bunker, and gets all four without being configured for them. That is the argument for putting this at the endpoint rather than in each developer's harness: a plugin can be disabled by editing a file, and a different harness simply never had it.

    1. 01 — inbound

      Screen what the agent reads

      A role: "tool" message is text the world just handed the agent. Secrets leak out here, and indirect prompt injection arrives here. Both are caught, and what remains is marked as data rather than instruction.

    2. 02 — charter

      Serve the standards

      Your team's pages, advertised as a ~600-token index rather than pasted into every prompt. A page costs nothing until it is opened, so the charter can be large.

    3. 03 — budget

      Measure, then refuse

      A session with no room to work is refused here, with the component responsible named — rather than failing downstream as a context-length error nobody can act on.

    4. 04 — outbound

      Refuse what the agent runs

      When the model answers with a tool call carrying a shell command, that command has not run yet. This is the one enforcement point no client can bypass.

    Rules that ship with their evidence

    A regular expression is the easiest thing here to get subtly wrong, and a wrong one fails silently: it stops matching, nobody notices, the guardrail is gone. So every rule carries its own examples, and they run in CI. 

    $ ai-bunker rules --check
  rules loaded                          17
  assertions passed                    107
  assertions failed                      0
  rules carrying evidence            100%

    Three shipped patterns were wrong on first write — including one whose bound could not cross the dot in ~/.aws/credentials. The examples caught all three before they reached a deployment.

    What it is not

    • Not a router with a hundred providers. LiteLLM is simply better at that, and ai-bunker sits in front of it rather than competing.
    • Not a content classifier. LLM Guard and Guardrails AI ship trained models; this ships versioned regular expressions. Reviewable and free to run — a trade, not a win.
    • Not mature. This is 0.1.0-alpha next to projects with years of production use.
