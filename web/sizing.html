    Sizing

    Which machine do you need?

    Capacity decides whether a model loads. Bandwidth decides whether it is usable. Sizing on the first and ignoring the second is how a machine with plenty of memory ends up answering too slowly to keep.

    The one fact that decides everything

    Generating a token requires reading every active weight out of memory once. So the ceiling on speed is arithmetic:

    tokens/second  ≤  memory bandwidth  /  active weight bytes

    Published DGX Spark measurements confirm it almost exactly. The GB10 has 273 GB/s: Qwen3 8B at bf16 (~16 GB) is measured at 13.6 tok/s against a roofline of 17.1, and Llama 3.1 70B at Q4 (~40 GB) at 4.4 tok/s against 6.8. This project assumes 70% efficiency, which is conservative against both.

    The word that does the work is active

    ModelTotalActive/tokenCeiling at 819 GB/s
    Devstral Small 2 24B, dense, FP825 GiB25 GiB~23 tok/s
    Qwen3-Coder-Next 80B/3B MoE, AWQ445 GiB~9 GiB~62 tok/s

    The best open coding model available is also the fastest to serve. Choosing a smaller model to go faster is, here, exactly backwards — and it is why the recommendation below costs less than it looks.

    For a small team, VRAM buys quality

    Two people need two concurrent sequences above 20 tok/s. That is a low bar, so the memory should go into a better model rather than into concurrency.

    The 48 GB NVIDIA card cannot run the best model at all. On NVIDIA the entry ticket is the 72 GB card at $12,600; on Apple it is a $5,600 Mac Studio, because unified memory is cheap and GDDR7 is not.

    The DGX Spark loses on bandwidth, not on memory. It has 128 GB and serves the best coder at 18 tok/s. Buying more of them does not help: bandwidth does not aggregate across machines for a single stream.

    The recommendation

    1. Step zero — free

      Measure the Mac you already have

      The arithmetic says a 96 GB M2 Max already serves Qwen3-Coder-Next at ~27 tok/s with a 256k window. That is a projection, not a measurement, and the difference is this project's entire argument — so pull the model, run a real session, and time a real patch before spending anything.

    2. If it is not enough — $5,600

      Mac Studio M3 Ultra 96 GB

      819 GB/s, twice the M2 Max, ~55 tok/s on the best open coder, holding the 80B model plus an 8B VLM plus the embedder at once. A complete machine: no chassis to spec, no 600 W card, no rack, 270 W and silent.

    3. If you need schema-constrained vision — $12,600

      RTX PRO 5000 Blackwell 72 GB

      The one thing Apple cannot do today. Driving a vision model from an agent means constrained decoding, vLLM has guided decoding, and vLLM has no macOS runtime — so vision + schema ⇒ Linux + discrete NVIDIA.

    The cheapest upgrade is not hardware

    The sizing is more sensitive to the average live context per session than to almost anything on the invoice — and that figure belongs to the harness, not to the card.

    An agent that pastes the whole standards document into every prompt, reads files whole instead of in slices, and never compacts halves the machine for identical output. That is the measurable argument for everything else here.

    A note on prices

    They moved violently and they are not done. The RTX PRO 6000 launched at $8,565 in March 2025 and sells for ~$16,000 today; the DGX Spark went from $3,999 to $6,950 for its 128 GB configuration. A 2026 sizing done on 2025 prices is wrong by a factor of two. Surveyed 2026-10-19; re-survey before buying.
