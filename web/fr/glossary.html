    Glossaire

    Chaque sigle,
    défini une fois.

    Un lecteur qui ne sait pas ce qu'est l'Agent Payments Protocol ne peut pas juger une affirmation à son sujet. Voici les termes employés par ce projet, au sens où il les emploie.

    A2A

    Agent2Agent

    Un protocole ouvert permettant aux agents de se parler : découverte par une carte d'agent, puis tâches et messages en HTTP, l'HyperText Transfer Protocol du web. ai-bunker publie une carte et filtre les messages entrants, car un message écrit par un autre agent est du texte qui franchit une frontière de confiance.

    A2UI

    Agent-to-User Interface

    Un agent décrit une interface qu'un hôte affiche, au lieu de renvoyer du texte. Utile, et nouvelle surface d'attaque : la description est produite par l'agent et l'hôte l'exécute.

    AP2

    Agent Payments Protocol

    Comment un agent prouve qu'un humain a autorisé un paiement. L'utilisateur approuve sur une Trusted Surface, que le protocole définit comme explicitement non-agentique, et l'agent porte le résultat signé — un mandat.

    UCP

    Universal Commerce Protocol

    La norme d'objet Checkout, utilisée avec un mandat AP2. Le mandat dit ce qui a été autorisé, l'objet Checkout dit ce qui est débité, et quelqu'un doit comparer les deux.

    MCP

    Model Context Protocol

    Comment un modèle atteint des outils et des sources de données. ai-bunker expose la charte via MCP, et seulement la charte.

    Agent Skills

    Un format ouvert pour empaqueter des connaissances qu'un agent charge à la demande : un dossier avec un SKILL.md, lu nativement par Claude Code, OpenCode, Cursor, Goose et d'autres. ai-bunker y publie sa charte.

    JWS / JWT

    JSON Web Signature / JSON Web Token — JSON pour JavaScript Object Notation

    Un jeton signé et compact, en trois parties séparées par des points — en-tête, charge utile, signature — encodé pour survivre dans une URL, une adresse web. Les mandats AP2 arrivent sous cette forme.

    JWKS

    JSON Web Key Set

    Les clés publiques contre lesquelles une signature est vérifiée. ai-bunker en lit un depuis un fichier par défaut, de sorte que vérifier un paiement ne demande aucun réseau.

    OTLP / OpenTelemetry

    OpenTelemetry Protocol

    La norme d'envoi de traces vers un collecteur. ai-bunker exporte son journal de décision en spans, car ce journal est déjà l'enregistrement de la trajectoire d'un agent.

    KV cache

    cache clé–valeur

    Ce qu'un modèle conserve des tokens déjà présents dans une conversation. Il croît avec le contexte et est relu à chaque token produit : c'est pourquoi le contexte coûte du débit et pas seulement de la mémoire.

    MoE

    Mixture of Experts — mélange d'experts

    Un modèle où chaque token n'active qu'une fraction des poids. Un MoE de 80 milliards dont 3 sont actifs lit moins de mémoire par token qu'un modèle dense de 24 : c'est pourquoi le meilleur codeur ouvert est aussi le plus rapide à servir.

    ReDoS

    Regular expression Denial of Service — déni de service par expression régulière

    Un motif dont le temps d'exécution explose sur une entrée fabriquée. Le chargeur de règles rejette les quantificateurs imbriqués non bornés avant de les exécuter : une sonde de temps ne peut pas attraper ce qui ne se termine jamais.

    Session floor

    Plancher de session

    La part d'une fenêtre de contexte payée à chaque requête — invite système, schémas d'outils, charte, index — et que la compaction ne peut pas réduire. Ce qui reste est le seul espace dont dispose une conversation.

    Slopsquatting

    Enregistrer un nom de paquet qu'un modèle est susceptible d'inventer, pour qu'un agent l'installe. Interroger un registre n'aide pas : le paquet malveillant est enregistré précisément pour que la réponse soit « oui ».

    Gherkin

    Un format de spécification comportementale en langage ordinaire : Given / When / Then. ai-bunker rend son jeu de règles en Gherkin pour que la personne qui l'approuve n'ait pas à lire des expressions régulières.
